# 開発環境

この PC（Windows 11）で開発・確認するときの環境の記録。

## Android の SDK とエミュレータ

ユーザー名に日本語が入っていると、Android のエミュレータは起動できない。エミュレータが内部の本体（qemu）に渡すパスの一部が文字化けし、起動に要るファイルを見つけられずに終わる。そのため、SDK と仮想端末（AVD）は ASCII だけのパスに置く。

| もの | 場所 |
|---|---|
| Android SDK | `D:\Android\Sdk`（Android Studio の SDK の場所もここ） |
| 仮想端末（AVD） | `D:\Android\avd`（ユーザーの環境変数 `ANDROID_AVD_HOME`） |
| エミュレータの作業場所 | `D:\Android\home\.android`（adb の鍵 `adbkey` を写してある） |
| エミュレータの一時ファイル | `D:\Android\tmp` |

`android/local.properties`（git に入れない）には `sdk.dir=D\:/Android/Sdk` を書く。

### エミュレータをコマンドから起動する

起動のときだけ、環境変数を ASCII のパスに向ける（PowerShell）。

```powershell
$env:ANDROID_SDK_ROOT = 'D:\Android\Sdk'
$env:ANDROID_AVD_HOME = 'D:\Android\avd'
$env:ANDROID_EMULATOR_HOME = 'D:\Android\home\.android'
$env:ANDROID_USER_HOME = 'D:\Android\home\.android'
$env:TEMP = 'D:\Android\tmp'; $env:TMP = 'D:\Android\tmp'
& 'D:\Android\Sdk\emulator\emulator.exe' -avd Medium_Phone_API_37.0 -no-window -no-audio
```

- `-no-audio`: エミュレータの音を PC のスピーカーに出すと、PC 側のループバックがそれを拾い、音が回り続ける。PC 側と合わせて確かめるときは音を出さない。
- エミュレータから見た PC は `10.0.2.2`。接続先は `10.0.2.2:48100`。
- adb は `D:\Android\Sdk\platform-tools\adb.exe`。Git Bash から `adb shell` で端末の中のパス（`/sdcard` など）を渡すときは `MSYS_NO_PATHCONV=1` を付ける（付けないと Windows のパスに読み替えられる）。

## Android のビルド

- JDK は Android Studio に付いているもの（`C:\Program Files\Android\Android Studio\jbr`）を `JAVA_HOME` に向ける。
- `cd android` → `./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug`
- ビルドするときは `ANDROID_USER_HOME` を付けない（SDK の場所は `ANDROID_HOME = 'D:\Android\Sdk'` で渡す）。付けると、デバッグ用の署名の鍵をそちらの `debug.keystore` から取り、いつもの `C:\Users\<ユーザー名>\.android\debug.keystore` と違う鍵で署名される。すると端末に入っている前の版へ上書きできず（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`）、入れ直すとペアリングの鍵が消える。`ANDROID_USER_HOME` はエミュレータを起動するときだけに使う。
- Release 版: `./gradlew :app:assembleRelease` → `android/app/build/outputs/apk/release/app-release.apk`。署名の鍵が無いと、署名していない APK（端末に入れられない）になる。
- lint は `local.properties` の変更を解析のやり直しのきっかけにしない。結果が古いときは `:app:lintAnalyzeDebug --rerun` を付ける。

## Release 版の署名の鍵

ふだん使うのは、自分の鍵で署名した Release 版（理由は docs/構成.md の 2.6）。鍵と合言葉は利用者が作り、git にも Claude にも渡さない。

1. 鍵を作る（合言葉を2回訊かれる。名前などの質問は空でよい）。置き場所はリポジトリの外にする。

   ```powershell
   New-Item -ItemType Directory -Force D:\Android\keys
   & 'C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe' -genkeypair -v -keystore D:\Android\keys\audioswitcher-release.jks -alias audioswitcher -keyalg RSA -keysize 4096 -validity 36500
   ```

2. `android/keystore.properties`（git に入れない）を作り、次の4行を書く。

   ```
   storeFile=D:/Android/keys/audioswitcher-release.jks
   storePassword=（1で決めた合言葉）
   keyAlias=audioswitcher
   keyPassword=（1で決めた合言葉）
   ```

- **鍵の控えを取っておく**。鍵を失うと、入っている Release 版に上書きできなくなり、入れ直すとペアリングの鍵・API キー・保存先の許可が消える。
- Debug 版は `io.github.tsarubucreate.audioswitcher.debug` という別のアプリになり、名前は「AudioSwitcher Debug」。Release 版と並べて入れられる。設定・ペアリング・API キーは別々に持つ。

## Claude のデスクトップアプリから起動したときの AppData

Claude のデスクトップアプリは MSIX パッケージのアプリで、その子プロセス（Claude が起動したシェルやアプリ）が `AppData` に書き込むと、Windows がパッケージ専用の置き場所に振り替える。そのため、Claude から起動した PC 側のアプリのログは、本来の場所ではなく次の場所に書かれる。

| 起動のしかた | ログの場所 |
|---|---|
| エクスプローラ・スタートメニューなど（普段の使い方） | `%LOCALAPPDATA%\AudioSwitcher\logs` |
| Claude のデスクトップアプリから | `%LOCALAPPDATA%\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Local\AudioSwitcher\logs` |

Claude の中から `%LOCALAPPDATA%\AudioSwitcher\logs` を読むと、振り替えた先の方が見えることがある。利用者が起動したアプリのログを Claude から読むときは、本来の場所の絶対パス（`C:\Users\<ユーザー名>\AppData\Local\AudioSwitcher\logs`）を PowerShell で読む。
